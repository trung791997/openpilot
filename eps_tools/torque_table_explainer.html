What a lookup table is

The EPS doesn't compute torque from a formula. It stores short lists of numbers (9 points each) and looks up a value for the current input, drawing a straight line between the two nearest points. The firmware stores values as whole numbers; a gain of 256 means ×1.0.

A request passes through three stages. The live values below follow the lookup section.

Tracker 0x137ee

1996 → 4500

How fast the EPS's internal model chases the command (2.25× stock). The -PTM file uses 4000. Raised on top of a hot D table, this caused a ~29 Hz hands-off limit cycle on a CR-V.

Feedback normalization 0x29efe

3429 → 1650

A divisor on the measured feedback. Smaller divisor means the feedback reads about 2.08× louder going into P and D.

Low-speed clamp 0x1361c

10 → 0

Speed floor below which assist is not allowed. Zeroed, like the "0 mph steering" patches on other Hondas.

The stutter, step by step

Why turning in fast makes the wheel stutter (toy model)

The attenuation table's input is column torque rate (how fast torque is changing), not column torque. When torque rises fast, the table scales the command down, as low as 156/256 ≈ 60%.

  1. Fast turn-in. A higher P gain makes the torque rise sharply, so the rate is high.
  2. Attenuation kicks in. High rate means the table cuts the delivered torque to about 60%.
  3. Error grows. The car turns less than asked, so the controller asks for more.
  4. Release. Once the rate falls, attenuation lets go, the larger request passes through in full, and torque overshoots.
  5. Repeat. The controller pulls back, the rate spikes again, and the cycle repeats. The driver feels a damp-push stutter.

The fix your friend described is moving the table's x-axis breakpoints up: attenuation then starts only at a higher rate, so a normal turn-in never triggers it. Try it below.
