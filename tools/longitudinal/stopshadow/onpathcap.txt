METHOD
- onpathcap/cap.py: radard runs from about 25 s before each event. The planners run over [t0-20, end+8]. One shared on-path planner is fed onpath_lead_view (its state is independent of the cap, as in production).
  There is one own planner per cap C in {1.0, 0.5, 0.3, 0.0}, plus one never bounded ("none" = no leadOnpath). Each keeps its own state including prev_output_a_target feedback.
  C = 1.0 is exactly production update().
- Contexts per frame (onpathcap/capana.py):
  - K = |yaw rate| / v from livePose.
  - NV = no leadsV3 entry with prob >= 0.5, |x - 1.52 - d| < max(5, 0.2 d) and |-y - yRel| < 2.5.
  - AZ = |azimuth| at the track's first radar point (a gap over 1 s counts as a new track) > 15 deg.
  The variant target is spliced per frame: capped planner where the context holds (held through frames without leadOnpath), production elsewhere.
  The splice is approximate at context on/off edges.
- Metrics per event over [first leadOnpath - 0.5 s, last + 5 s]. "min" rejects single-frame dips and is taken over the leadOnpath span + 1.5 s.
  Brake start = the first target below -0.3 (inf = never). dx = double integral of the target difference (open-loop proxy, + = nearer the car).
- Not reproduced in the segment-start harness (9): listed at the end of the detail. Some QP "status 3" solver messages appeared in the log; the -3.50 values are the planner's own clip.
